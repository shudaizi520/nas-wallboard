# NAS Wallboard

天气预警文字按数据源的颜色分别显示（橙色、黄色等），不再把正常温度和天气一起染红。没有颜色时按严重程度保留提醒；预警解除或更新失败的说明仍完整显示。查询频率和预警判断不变。

面向 **TrueNAS SCALE 25.10+** 的轻量桌面状态小组件。NAS 上只运行一个非 root Go 进程；浏览器和 Windows 桌面端共用同一套界面，不需要 Rainmeter，也不需要用户编辑配置文件。

## 能显示什么

- CPU 使用率与温度、可用内存、网速、机械硬盘温度与 SMART 告警
- 存储池容量、TrueNAS 告警、应用异常、复制任务异常
- 天气和预警
- Plex / Jellyfin 多终端播放（每个会话单独一行）
- qBittorrent、Uptime Kuma、Home Assistant、Scrutiny
- 可在网页中添加、禁用、排序和设置组件，桌面实时复用结果

空闲的媒体来源每分钟查询一次；检测到播放后才提高到 15 秒。停用的集成不会在后台发请求。Windows 客户端空闲时不持续重绘，典型任务管理器占用应稳定在 0% CPU 附近。

CPU 使用率读取 TrueNAS Netdata 的总 `cpu` 百分比，每 5 秒取最近有效采样，不相加各核心、不推算瞬时值；空采样会标记不可用，不冒充 0%。读数与另一个界面不在同一采样时刻时可能不同。CPU 计算口径由 TrueNAS 决定：已核对的 25.10.7 实现会把 `/proc/stat` 的 guest 时间再次计入总时间，运行虚拟机时可能比排除重复 guest 的 Linux 常规算法偏高；Wallboard 不修改 NAS 的采样服务。

实时网速可在既有组件设置中选择 NAS 网络接口，接收和发送取同一个接口的同一条完整采样，不把多个物理、桥接或虚拟接口相加。指定接口不可用时显示「—」，不会偷偷改选其他接口或补零；选项使用已有采集缓存，不增加 NAS 请求。见 [网络接口说明](docs/network-interface.md)。

天气的当前、降雨、官方预警和日预报独立刷新；部分接口失败时仍显示成功的部分，并注明不可用。尚未过期的官方预警在临时失败时保留为“上次预警”，不会当成新预警续期。英制选项仅转换显示温度，危险阈值仍使用公制。

在设置界面配置的天气和 Scrutiny 集成，启动或采集失败后允许最多三次提前重试，等待间隔依次为 1、2、4 分钟；仍失败时恢复低频查询，不会一直高频重试。天气仅重试失败的子接口，已成功的子接口沿用原有缓存和刷新间隔；失败不会更新成功时间或延长缓存有效期。恢复成功后回到正常查询频率，其他采集器的频率不变。

天气名称与提示按内容自动换行，不限制为一行或两行；短内容不留多余空行，长内容会推开后续条目并同步调整桌面窗口高度。多条有效预警按严重程度逐条显示，不再用“+2”等计数隐藏其他预警。发布或更新预警时可精简机构前缀，保留灾种、等级和原始颜色；仅说明“更新为黄色”等不完整标题不会被错误截短。界面宽度、其他状态行的列对齐和查询频率保持不变。

天气采用苹果式五天逐行预报（今天及之后四天）：沿用内置图标，每行显示日期、天气图标、最低温、温度范围条和最高温，非零降水概率放在图标下方。五天使用同一温度刻度，今天的白点表示当前温度；当前读数缺失、单位不一致或超出今天预报范围时不画白点，不伪造位置。当前温度及天气描述保留在上方，文字提醒紧接其后；这里只保留临近降雨、强风、强紫外线、正式预警及数据不可用说明，正常无雨时留空，不常驻体感/湿度。每天的强风/紫外线说明保留在点击详情里，不重复铺在列表中。正式预警不会覆盖仍有效的临近降雨提示。

当前天气与五天预报之间可显示一排六个关键小时：从未来十二小时内优先选降雨、降雪、强风及天气变化前后的时段，平稳天气适当拉开间隔；时间标签明确标注，不要求滑动。跨午夜的小时栏只显示钟点（如“0时”），不额外增加“次日”文字行或占位；底层时间、无障碍标签和跨日文字提醒仍保留日期区分。当前实测只在上方大字号天气栏显示，小时栏的六个位置全部用于未来预报，不重复显示“现在”；样本不足时不伪造数据补满，当前接口不可用时不会用预测冒充实测。小时预报读取24个样本，每30分钟刷新一次；集成中心的“智能小时预报”开关可关闭该接口。过期或失败时隐藏旧小时数据并注明不可用，不影响健康的其他天气来源。

天气输入会区分缺失温度与真实零度；缺失/空温度或无效天气现象不会更新成功时间，也不会覆盖旧实测。预警按接口的取消、更新及取代关系处理，不把取消消息显示成新的警报；缓存预警到自身失效时间即撤下，不增加请求。异常响应缺少预警列表时会提示更新失败，并保留尚未过期的上次预警；明确的空列表或 `metadata.zeroResult=true` 才表示合法无预警。缺少失效时间的兼容数据仍受来源缓存有效期限制。

小时降雨/降雪提醒、关键时段选择与图标使用同一套降水依据：明确的降水现象优先，非降水现象可由有效预测降水量或至少30%的有效概率补充“可能有雨/雪”。保留雷阵雨等原始现象图标；仅低概率、没有其他降水依据时不强行改成雨图标。不推算或补造概率，原始描述和概率保留在数据中，补充风险只影响未来小时，不改变当前观测。

“今天”的图标可由有效小时预报概括当地当天剩余时段的主要天气，不再仅因短时小雨就把整行定成雨天；使用现有图标，短时降水仍保留在小时栏和时间提醒里。需要最近时段至当地午夜的连续覆盖，缺失、重复、过期或失败时回退日预报。连续至少3个小时、占剩余样本至少一半的降水，以及雷雨、降雪、较强降水仍保留降水图标；日预报的雷雨、降雪和较强降水不因小时数据不一致而被降级。这是保守的显示策略，不是新的气象预测。仅调整今天的图标及描述，不改变当天最高/最低温、来源日降水概率、后续日期、当前观测或查询频率；原日夜预报和概括依据保留在详情中。

右侧普通提醒每6秒在客户端本地轮播，单条固定、无有效消息留空，不增加NAS或天气接口请求；官方预警、当前强风、临近降雨和数据故障说明保持可见。相同数据刷新不会重置轮播，网络失败会停止普通轮播并注明过期，保留已知重要预警。近期雨仅与完全重叠的两小时内雨段去重，独立晚间雨和持续更久的雨段仍保留。

当前和小时晴天图标复用日预报已有的当地日出日落时间，夜间显示月亮；缺失、无效或过期天文数据时保留通用天气图标，不根据NAS时区或固定钟点猜测。零下温度正常显示，“冷”不会被当成降雪；非有限温度和无效概率仍拒绝。日期字号、五天行高与其他项目名称不变，小时排没有概率时自动收紧空行，窄桌面仍保持紧凑底边。

点击某天可展开白天/夜间预报和风险详情，再次点击收起；桌面鼠标穿透锁定时请先解锁或在网页查看。百分比展示白天/夜间中较高的已知降水概率，详情标明对应时段，不把它当作合并计算的全天概率；最终图标非雨、雪、雷雨时，小时栏和五天列表省略显示值低于20%的小概率，详情和来源数据不变。雨雪雷雨图标仍保留已知低概率，包括“<1%”；缺失或无效值不会冒充 0%。预报数据不足五天时只显示实际可用日期，不填造数据；旧页面仍可读取兼容的两行预报。

智能小时栏先保留降雨、降雪、强风风险时段，再选持续晴与多云/阴之间的转折，以及3小时内至少降温4°C且下一小时不立即回升的较强降温两端。普通天气转折须两侧各有两个连续同类样本，不把一小时波动、晴与少云的小变化或日夜图标切换当成转折；剩余位置沿用约两小时间隔，不增加位置或请求。这仅是缓存样本的显示取舍，不是新的气象预警。

极长内容超过窗口或屏幕可用高度时保留滚动查看的能力，窗口仍保留安全尺寸上限。桌面端锁定时鼠标会穿透，无法直接用滚轮操作；这种情况下可打开同一 NAS 的网页查看全部内容，不改变桌面的锁定/移动策略。普通一至三行内容仍直接展开，不需要滚动。

分钟降雨同时检查接口的 `updateTime` 和每个 `fxTime`；超过 30 分钟的旧响应、无效时间或已结束的预报不会当作最新降雨。提示按实际预报时刻随时间推进，不靠数组位置计算；剩余覆盖不足两小时，也不会声称完整的“两小时无雨”。日预报按地点的时区和起止日期筛选日期，跨午夜自动把有效的下一天移到“今天”，去除已结束的旧日期，不更新来源成功时间或延长有效期。五天日预报仍只用一次请求。这些计算只使用缓存，不增加请求频率（当前/降雨 10 分钟、官方预警 5 分钟、日预报 1 小时）。当前天气接口未提供观测时间，程序只能记录成功获取时间，不能保证上游观测本身一定最新；天气预测也不等于实测或保证。

## 安装

1. 在 GitHub Releases 下载 `nas-wallboard-truenas.yaml` 和 `SHA256SUMS`，先核对校验值。
2. TrueNAS 打开 **Apps → Discover Apps → Install via YAML**，粘贴 YAML 并保存。
3. 打开 `http://你的-NAS-地址:18082/setup`。
4. 按向导创建并验证 TrueNAS 专用只读账户/API Key，再设置 Wallboard 管理密码。
5. 在 `/manage` 添加集成、选择组件；点击“安装桌面小组件”下载已写入当前 NAS 地址的 Windows ZIP。

详细步骤、升级和回滚见 [TrueNAS 安装说明](docs/truenas-install.md)，桌面端见 [Windows 小组件说明](docs/windows-desktop-widget.md)。

管理页概览分别显示 NAS 服务版本、服务器提供下载的客户端版本，以及从桌面客户端打开时携带的本机版本。普通浏览器无法识别已安装的桌面客户端，不会猜测版本或声称它已更新。更新 NAS 服务后，桌面外壳本身如需升级仍须退出并替换可执行文件；刷新只会重新加载页面。

## 安全设计

- 只支持 TrueNAS SCALE 25.10+ 的 WebSocket JSON-RPC API，不调用 TrueNAS 删除或修改接口。
- API Key、Token 和密码只保存于 `/data/secrets` 或 Argon2id 密码记录；管理 API 永不返回原值。
- `/manage` 需要本地密码会话、同源校验与 CSRF；完整备份和恢复出厂还要求一次性重新认证。
- “集成中心”仅使用编译进程序的内置集成，不下载或执行第三方插件。
- 容器为 UID/GID 65532、只读根文件系统、无 Docker Socket、全部 capabilities 丢弃，并限制为 512 MiB、0.5 CPU、64 PID。内存是上限而非预留；完整加密备份的密码运算短时需要约 256 MiB，正常采集不会占满这个上限。

“设置与恢复”支持完整加密备份的下载和导入。导入需当前管理员密码、备份密码及明确确认，先校验文件再替换配置，恢复后使用备份中的账号登录；未完成的替换会在下次启动时回滚。Home Assistant 配置中的“读取风扇与功耗设备”可列出风扇及 W/kW 功率传感器，仍支持手填实体。“概览”可展开查看各采集器的最后成功时间。
- 应用定位为可信局域网工具，不要直接映射到公网；需要跨网访问时请使用自己维护的 TLS VPN 或反向代理。

## 备份与排障

管理页“设置与恢复”可下载两种文件：

- 脱敏诊断 ZIP：不含密钥，适合提交 Issue。
- 完整加密备份：包含配置与密钥，必须重新验证管理员密码，并用至少 12 字符的独立密码加密。

不要把完整备份、API Key、Cookie、硬盘序列号或未经检查的日志上传到公开 Issue。

## 从源码验证

```sh
go test -race ./...
go vet ./...
npm ci
npm test
npm run test:e2e
dotnet test windows/NASWallboard.Desktop.sln -c Release
```

本地镜像先运行 `make image`；它会构建 Windows 客户端，并把同一份可执行文件嵌入服务镜像。公开版本由标签触发的流水线生成 digest 固定的镜像、TrueNAS YAML、Windows ZIP、SHA-256 校验和与 SPDX SBOM。
